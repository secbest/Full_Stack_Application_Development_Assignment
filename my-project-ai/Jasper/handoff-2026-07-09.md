## Session 1 - Wave 2B: Pricing Contracts Feature (Backend + Frontend + Review Fixes)

### What We Worked On

Built the entire Wave 2B scope end-to-end: the `pricing_contracts` / `pricing_rates` / `surcharge_schedules` CRUD backend, the three Pricing Contracts frontend screens (List, Detail, Create/Edit), a supporting `GET /api/clients` endpoint, then iterated through a series of real bugs found via manual testing and a formal design-doc review, fixing all of them.

1. **Backend CRUD** - all 8 documented endpoints in `design/jasper/api-documentation.md` §1-3 (`GET/POST /api/contracts`, `GET/PATCH /api/contracts/:id`, `POST/PUT/DELETE .../rates[/:id]`, `PUT .../surcharges/:id`), plus a minimal `GET /api/clients` (not in the original doc - added because nothing in the app exposed a client list yet, and the contract form needs one for its client picker).
2. **Frontend pages** - `PricingContractPage.jsx` (List, replacing the old placeholder), `ContractDetailPage.jsx` (Detail, inline rate/surcharge management), `ContractFormPage.jsx` (Create/Edit), plus supporting `api/contracts.js`, `validation/contractValidation.js`, `lib/contractLabels.js`, and shared components `FieldError.jsx`/`MiniSelect.jsx`.
3. **Bug-fix rounds from manual testing** (reported via screenshots as the pages were used):
   - Dropdown text wrapping onto two lines in the rate table - fixed with `whitespace-nowrap` on the select trigger.
   - That fix then squeezed the chevron icon out of view entirely on longer labels - root cause was Radix's `Select.Value` silently dropping any `className`/`style` passed to it; fixed by wrapping it in a plain `<span>` we control instead, plus `shrink-0` on the icon in the shared `ui/select.jsx`.
   - Table columns shifting position depending on which option was selected - fixed with `table-fixed` + `<colgroup>` percentages (table context) and `minmax(0, 1fr)` grid tracks (the equivalent CSS Grid fix, same root cause: content-based sizing).
   - **Real logic bug**: creating a contract with a future `effective_from` showed "Expired" instead of a sensible status, and would have *silently never activated* even after its start date passed - `is_active` was only computed once at write time and nothing ever recomputed it. Redefined `computeIsActive()` to only depend on `effective_to` (lapsed vs. not), so the pricing engine's existing date-range query at match time does the real "is this active right now" check, matching the fact that this app has no cron/scheduled job.
   - Added a 4th "Deactivated" display status (manually withdrawn, distinct from naturally "Expired") derived from `is_active` + dates with no new DB column - the proof: the automatic code path only ever sets `is_active=false` when lapsed, so `is_active=false` with a still-current `effective_to` can only mean a manual PATCH.
   - Added a "Show inactive contracts" toggle (default off) on the List page so Deactivated/Expired contracts don't clutter the default view, after discussing and rejecting a real-delete feature for now (see Key Decisions).
4. **Design-doc review** - a structured review against `design/jasper/api-documentation.md` and `use-cases.md` across 5 categories (unimplemented flows, hardcoded values, missing error handling, frontend/backend validation drift, code that would be hard to defend in a technical review). Found 20 issues; fixed 18 with code changes and resolved 2 as documentation-only decisions (see below).
5. **Committed to `wave-3-ap-sync`** (not `main`) at the user's request, so a teammate can review before it's merged - commit `75caed4`, currently local-only (not yet pushed to `origin/wave-3-ap-sync`).

### Key Decisions Made

- **Backend + frontend both in scope for Wave 2B**, rather than frontend-only against a not-yet-built API - user's explicit choice when the backend was found to not exist yet.
- **`RATE_IN_USE` is a coarse, contract-level check**, not per-rate - `invoice_line_items` has no `rate_id` FK to trace a specific rate to a specific invoice (that's Wave 3's schema, owned by Kwan Hua). User chose the conservative option (block deletion whenever the contract has *any* billing history) over adding a new FK to Wave 3's tables or skipping the check entirely.
- **Three deliberate deviations from the Figma Make mockup** (`Design login screen for EFAR/src/app/ARApp.tsx`): the create form includes a Surcharge Schedule section (the mockup doesn't have one, but there's no `POST .../surcharges` endpoint - surcharges can *only* be set at contract creation, so omitting it would leave every contract permanently short a surcharge schedule); no "+ New Client" modal (no backend client-create endpoint exists - Client stays Zheng Bao's owned table); "Cancellation" surcharge is a dollar amount, not the mockup's `"100%"` string, matching the real `DECIMAL` column.
- **`is_active` semantics redefined**: means "not lapsed / not manually withdrawn," not "currently within the date range." This was a real bug fix, not just a naming choice - see the bug-fix list above.
- **Hide-inactive-by-default over real deletion** - when contracts started cluttering the list, chose a pure UI toggle (default hides Deactivated/Expired) over building a delete feature, since deleting a contract with invoice history would break the audit trail. Real deletion (for genuinely never-used contracts only) was discussed and explicitly deferred, not rejected outright.
- **Deactivate is available for "Upcoming" contracts**, not just "Active" ones - once `is_active` correctly defaults to `true` for a not-yet-started contract, deactivating it is the correct way to cancel a renewal before it ever starts, not the no-op it would have been under the old (buggy) semantics.
- **A Postgres advisory lock (`pg_advisory_xact_lock`) closes a TOCTOU race** on the contract-overlap check, instead of a DB migration - two near-simultaneous creates for the same client could previously both pass the overlap check before either committed.
- **Response envelope mismatch left as a documentation fix, not a code change**: the API doc specifies `{error, message}`; the real, working shape is `{success, code, message}` used consistently by *every* controller in the whole app, not just this feature. Changing the code would either break every other feature's existing frontend calls or make this feature inconsistent with the rest of the app - neither is better than the current state. Updated the doc instead (`design/jasper/api-documentation.md`).
- **Two hardcoded pricing-figure lists (`seed-pricing.js` and `contractLabels.js`) were left duplicated**, not merged into a shared config - a Node backend script and a Vite frontend bundle don't share a module system without new shared-package tooling, which is disproportionate for "two lists of default dollar amounts might drift." Added explicit bidirectional cross-reference comments instead.
- **Committed everything as one commit** on `wave-3-ap-sync` rather than splitting into several - it's one cohesive feature (build + fix + review-fix), and the user didn't ask for finer-grained history.
