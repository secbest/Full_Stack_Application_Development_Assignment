### Key Decisions Made

- **A visual "bug" isn't always a bug - trace the actual mechanism before fixing.** The black focus rectangle was correctly diagnosed as Recharts' built-in accessibility behavior (not broken code) before deciding how to suppress it, the same way last session's "Current Job stuck" report turned out to be a second seeded booking, not stale state.
- **Match existing terminology instead of the user's literal wording when it's slightly off.** The user suggested "Account Receivable role" (singular, a typo of the actual term); used "AR Specialist role" instead, matching the exact role name already shown elsewhere in the app (sidebar badge, role filter dropdown).
- **Default period was chosen by judgment, then corrected on request.** Set "This Month" as the default in the first pass (reasoning: "Today" as default would make Reports look empty most days), explained that reasoning to the user, then changed it to "Today" without pushback when explicitly asked in a follow-up message - the earlier reasoning was a recommendation, not a hard requirement.
- **Zero-value chart entries are dropped, not displayed as `$0 · 0%`.** A service type the client did no business in adds nothing to a "where did revenue come from" chart and just clutters the legend.
- **Verify the actual merge, don't just eyeball the diff.** Used `git merge-tree` (dry-run, no side effects) before ever running a real `git merge`, and ran the full test suites (not just the files touched by the conflict) after every merge step - this caught both post-merge test breaks before they reached `main`.
- **When main moved mid-push, re-verify from scratch rather than force-pushing over it.** Fetched, dry-ran the new merge, actually merged, re-ran both full test suites again, and only then pushed - treated the second, unplanned merge with the same rigor as the first rather than assuming a quick conflict-free merge needed less scrutiny.
- **Kept main's corrected business logic over this branch's version where the two genuinely disagreed.** In the `dashboardController.js` conflict, main's GST-aware gross/net split was the substantive fix; this branch's contribution to that same function was purely structural (the try/catch). Preserved main's math and adapted the test's expectations to it, rather than the reverse.
