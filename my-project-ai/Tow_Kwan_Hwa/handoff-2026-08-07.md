# Session Handoff - 2026-08-07 (Kwan Hua)

## Summary

Completed and merged the AP workflow improvement branch into `main`. The work makes vendor
invoice processing recoverable end-to-end: manual recovery after OCR failure, secure email and
Gmail intake, current Gemini OCR support, stronger GST/Xero validation, retryable Xero failures,
and Managing Director access to monitor Gmail intake. The branch merged without conflicts.

After live testing, two production-path defects were fixed on `main`:

- OCR could return `GST = 0` even when it had read a GST-exclusive subtotal and GST-inclusive
  total. The service now safely derives only a 7%, 8%, or 9% Singapore GST difference and marks
  it for source-document confirmation.
- AP approval attempted to lock the nullable line-item side of an outer join. PostgreSQL rejected
  this with `FOR UPDATE cannot be applied to the nullable side of an outer join`. Approval now
  locks only the parent vendor-invoice row, retaining the duplicate-approval safeguard.

`main` is pushed and synchronized with `origin/main` at `07d283b`.

## Delivered Work

### AP review, validation, and recovery

- When upload OCR fails after the PDF has been stored, the saved `extraction_failed` invoice opens
  directly for manual entry rather than leaving the user at an unusable upload modal.
- Header fields and line items remain editable while the invoice is pending review, has an OCR
  extraction failure, or has a failed Xero sync. Re-extraction preserves the existing document and
  data if Gemini fails.
- AP approval validates required fields, due date, line arithmetic, date-effective GST snapshot,
  supplier GST registration for standard-rated bills, subtotal + GST, rebate/net total, and Xero
  expense account.
- Failed Xero syncs remain recoverable through Xero Sync Status and retain a clear failure reason.
- Vendor invoice list status counters are queue-wide and remain correct when a status filter is
  selected.

### Email intake

- Added generic inbound-email endpoint `POST /api/vendor-invoices/inbound-email` for an email
  provider to submit PDF attachments using a server-side shared secret.
- Added idempotency based on mail message ID and attachment index, so provider retries do not make
  duplicate vendor invoices. Run `npm run db:migrate:ap-inbound-email` for existing environments.
- Added personal Gmail intake: the Managing Director connects Gmail, labels messages
  `EFAR AP Invoices`, can run an immediate import, and the server polls every five minutes. A
  successfully imported message receives `EFAR AP Processed`.
- Gmail intake migration: `npm run db:migrate:gmail-intake`. Configuration and manual test steps
  are in `docs/AP_INBOUND_EMAIL_INTAKE.md`.
- Gmail OAuth prerequisites that must be completed outside the repository:
  - Add the Gmail account as a Google OAuth test user while the Google app is in testing.
  - Put the exact current Google OAuth client secret in `GOOGLE_GMAIL_CLIENT_SECRET`; a changed
    secret requires restarting the backend and reconnecting Gmail.
  - Never commit Gmail client secrets, refresh tokens, or inbound-email secrets.

### OCR and GST

- Replaced retired `@google/generative-ai` usage with `@google/genai` and the configured current
  Gemini model. The default is `gemini-3.6-flash`; environments can override it through
  `GEMINI_MODEL`.
- The OCR prompt explicitly says not to use `0` as a placeholder for unread GST.
- For the Central Medical example (subtotal `1343.00`, total `1463.87`), the recovery logic derives
  GST `120.87` / 9% and routes it through low-confidence source verification. The AP user should
  still check the PDF and enter the supplier GST number when needed.

### Xero behaviour and outstanding configuration

- The AP Xero payload continues to send the invoice's real currency. It must not be silently
  changed to the Xero organisation's base currency.
- Live Xero returned: `Organisation is not subscribed to currency SGD`. This is an external Xero
  organisation configuration issue, not an EFAR field-validation issue.
- The connected Xero organisation needs SGD as its base currency, or a multicurrency-enabled plan
  with SGD added in **Organisation name -> Settings -> Currencies**. After that, retry the failed
  bill from **Xero Sync Status**. The bill stays recoverable in EFAR.
