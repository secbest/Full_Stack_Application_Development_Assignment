## Wave 3 - AR Billing (taken over from Jasper)

**Backend**
- Pricing engine: `backend/src/services/pricingService.js` (pure, unit-tested) - base-rate lookup
  (office / non-office / all_hours) + all published surcharges (oxygen base + per-litre over 10L,

  >=90 kg, Jurong Island).
- `backend/src/controllers/memoReviewController.js`: `GET /api/service-memos/pending-review`,
  `PATCH /api/service-memos/:id/approve` (runs the engine + generates the invoice in one
  transaction; `unmatched` + 422 when no contract / no matching rate), `PATCH /:id/return`.
- `backend/src/controllers/invoiceController.js`: `GET /api/invoices`, `GET /api/invoices/:id`,
  line-item add/edit/delete, `POST /api/invoices/batch-approve`, `POST /api/invoices/:id/retry-xero`.
  AR sync writes `xero_sync_logs` with `entity_type='ar_invoice'` and advances the booking + memo to
  `invoiced` on success (reuses the AP simulation-mode Xero service via `pushArInvoice`).
- Schema touches applied by `db:sync`: added `ServiceMemo.ar_note`; relaxed `Invoice.contract_id`
  to nullable (needed for `unmatched` invoices).
- Seed: `backend/src/scripts/seed-pricing.js` (`npm run db:seed:pricing`) - TTSH contract + rates +
  full surcharge schedule + submitted memos on completed bookings (3 matched cases + 1 uncontracted
  case to exercise `unmatched`).
- Tests: `backend/tests/kwan-hua/pricing.test.js` (17 cases). Full backend suite: 34 passing.
