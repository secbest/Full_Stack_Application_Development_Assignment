## Cross-Team Notes

- **Liang Yi** must add `booking_id` as a foreign key on `service_memos` so that a submitted memo can be linked back to its originating booking.
- **Jasper** references `bookings.id` on the `invoices` table (`invoices.booking_id`). The `bookings` record must exist and have a valid `client_id` before Jasper's pricing engine can match an invoice.
- The `clients` table is a shared group table. When Camilla confirms an intake submission (UC-03), the application layer must look up or create the `clients` record and set `bookings.client_id` before saving the booking.

## Table: `intake_submissions`

Stores each raw customer request submitted through the public intake portal. A submission moves from `pending` to `confirmed` (when a booking is created) or `rejected`. No booking exists until Camilla explicitly confirms the submission.

| Field | Sequelize Type | Constraints |
|-------|---------------|-------------|
| `id` | `DataTypes.INTEGER` | Primary Key, Auto Increment |
| `reference_number` | `DataTypes.STRING(20)` | NOT NULL, Unique - e.g. `EFAR-2026-00001` |
| `customer_name` | `DataTypes.STRING(255)` | NOT NULL |
| `organisation` | `DataTypes.STRING(255)` | allowNull: true |
| `contact_email` | `DataTypes.STRING(255)` | NOT NULL |
| `contact_phone` | `DataTypes.STRING(20)` | NOT NULL |
| `service_type` | `DataTypes.ENUM('eas', 'mts', 'event_standby', 'workplace_standby')` | NOT NULL |
| `service_tier` | `DataTypes.ENUM('basic', 'advanced', 'critical')` | NOT NULL |
| `preferred_date` | `DataTypes.DATEONLY` | NOT NULL |
| `preferred_time` | `DataTypes.STRING(10)` | NOT NULL - stored as `HH:MM` string (e.g. `14:30`) |
| `pickup_location` | `DataTypes.TEXT` | NOT NULL |
| `destination` | `DataTypes.TEXT` | NOT NULL |
| `additional_notes` | `DataTypes.TEXT` | allowNull: true |
| `status` | `DataTypes.ENUM('pending', 'confirmed', 'rejected')` | NOT NULL, Default: `'pending'` |
| `rejection_reason` | `DataTypes.TEXT` | allowNull: true - required when status = `rejected` (UC-04) |
| `reviewed_by` | `DataTypes.INTEGER` | allowNull: true, Foreign Key → `users.id` - set when Camilla confirms or rejects |
| `reviewed_at` | `DataTypes.DATE` | allowNull: true |
| `created_at` | `DataTypes.DATE` | Auto-managed by Sequelize |
| `updated_at` | `DataTypes.DATE` | Auto-managed by Sequelize |

### Notes on Fields

- `reference_number` is generated by the backend on intake form submission using a sequential counter or UUID prefix. It is shown to the customer in their confirmation message (UC-01, step 6).
- `service_type` stores the real EFAR service category selected by the customer. Values match the ENUM used on `service_memos.service_type` (Liang Yi) and `pricing_rates.service_type` (Jasper) for consistency.
- `service_tier` is the customer-facing classification (Basic / Advanced / Critical). Camilla may adjust this during booking confirmation (UC-05) - the adjusted value is stored on `bookings`, not here. This field preserves the customer's original selection for audit.
- `reviewed_by` is null while the submission is in `pending` status and is set to Camilla's `users.id` when she takes action.

## Table: `bookings`

Stores confirmed service jobs. Created by Camilla when she approves an intake submission (UC-03). The booking is the central record linking the intake request, assigned crew, field service memo (Liang Yi), and invoice (Jasper).

| Field | Sequelize Type | Constraints |
|-------|---------------|-------------|
| `id` | `DataTypes.INTEGER` | Primary Key, Auto Increment |
| `reference_number` | `DataTypes.STRING(20)` | NOT NULL, Unique - e.g. `BKG-2026-00001` |
| `intake_submission_id` | `DataTypes.INTEGER` | allowNull: true, Foreign Key → `intake_submissions.id` |
| `client_id` | `DataTypes.INTEGER` | NOT NULL, Foreign Key → `clients.id` (Group shared) |
| `created_by` | `DataTypes.INTEGER` | NOT NULL, Foreign Key → `users.id` - Camilla's user ID |
| `assigned_crew_id` | `DataTypes.INTEGER` | allowNull: true, Foreign Key → `users.id` - set when crew is assigned (UC-06) |
| `service_type` | `DataTypes.ENUM('eas', 'mts', 'event_standby', 'workplace_standby')` | NOT NULL |
| `service_tier` | `DataTypes.ENUM('basic', 'advanced', 'critical')` | NOT NULL - Camilla's confirmed tier, may differ from the intake submission |
| `original_service_tier` | `DataTypes.ENUM('basic', 'advanced', 'critical')` | allowNull: true - populated only when Camilla adjusts the tier (UC-05 audit trail) |
| `scheduled_date` | `DataTypes.DATEONLY` | NOT NULL |
| `scheduled_time` | `DataTypes.STRING(10)` | NOT NULL - stored as `HH:MM` string |
| `pickup_location` | `DataTypes.TEXT` | NOT NULL |
| `destination` | `DataTypes.TEXT` | NOT NULL |
| `status` | `DataTypes.ENUM('confirmed', 'in_progress', 'completed', 'invoiced')` | NOT NULL, Default: `'confirmed'` |
| `notes` | `DataTypes.TEXT` | allowNull: true - internal notes added by Camilla |
| `created_at` | `DataTypes.DATE` | Auto-managed by Sequelize |
| `updated_at` | `DataTypes.DATE` | Auto-managed by Sequelize |

### Notes on Fields

- `intake_submission_id` is nullable to allow bookings to be created directly by staff without going through the public intake form. In the current scope all bookings originate from an intake, but the nullable constraint avoids a hard dependency between the two tables.
- `service_tier` is the final confirmed tier set by Camilla. `original_service_tier` captures the customer's original selection only when Camilla changes it. If Camilla confirms without adjusting the tier, `original_service_tier` is null.
- `status` transitions are partially driven by other team members' features: `in_progress` and `completed` are set by Liang Yi's field memo flow; `invoiced` is set by Jasper's system after a successful Xero sync. Expose a `PATCH /bookings/:id/status` endpoint so other services can update status without full ownership of this table.
- `assigned_crew_id` references the `field_crew` role in the shared `users` table. It is nullable until Camilla assigns crew (UC-06) and can be reassigned at any time while status is `confirmed` or `in_progress` (UC-06 alternative flow).

## Status Flow Reference

### `intake_submissions.status`

```
pending → confirmed (Camilla clicks Confirm Booking - UC-03)
        ↘ rejected  (Camilla clicks Reject + enters reason - UC-04)
```

Rejected submissions can be reopened to `pending` within a configurable time window (UC-04 alternative flow), provided no booking has been created from them.

### `bookings.status`

```
confirmed   (Booking created by Camilla - UC-03)
  → in_progress  (Crew activates job on site - Liang Yi's flow)
  → completed    (Field memo submitted by crew - Liang Yi's UC-05)
  → invoiced     (Jasper's pricing engine matches and Xero sync succeeds - Jasper's UC-07)
```

The `completed → invoiced` transition is triggered by Jasper's service after a successful Xero sync, not by Camilla or Zheng Bao's code directly.
